# Vibration Dashboard

Local Streamlit dashboard for analyzing vibration dataset with daily feature trends and spectral band heatmaps.

## Features

- **Daily feature trends**: Median with 10th–90th percentile bands for all features (RMS, kurtosis, crest, skewness, peaks, spectral bands)
- **Observation count/coverage**: Daily sample count to visualize data density and gaps
- **Spectral band heatmap**: 15-minute median bins across 16 frequency bands (band_01_db through band_16_db) for each axis
- **Machine/axis/feature/date selectors**: Interactive filtering

## Quick Start

```bash
# Install dependencies
pip install -r requirements.txt

# Preprocess data (run once, creates cache files)
python preprocess.py

# Launch dashboard
streamlit run app.py
```

## Data Source

The dashboard reads from the compressed CSV files in `../thesis-dataset/thesis-dataset/data/`:
- `machine_01.csv.gz` through `machine_06.csv.gz`

The preprocessing script:
1. Streams each `.csv.gz` file directly with pandas (no manual extraction)
2. Computes daily statistics (median, p10, p90, count) for all features
3. Computes 15-minute median bins for spectral bands (heatmap data)
4. Saves compact Parquet cache files under `cache/`
5. Preserves original compressed dataset unchanged

## Visual Design

- **Dark graphite interface** (`#1a1a2e` background)
- **Cool blue spectral intensity scale** (Plotly `Blues` colorscale)
- **Amber indicators** for observation counts and sparse coverage (`#ffc107`)
- **Accessible contrast** for all text and chart elements

## Important Notes

- All dates are **shifted** — original timestamps have been offset
- Dataset contains **no raw waveforms**, machine-state labels, fault labels, or anomaly labels
- Band values are **relative dB** measurements from 16 recorded spectral bands
- The heatmap is a **spectral band heatmap** (not a reconstructed spectrogram)
- Sparse periods and long gaps are shown as-is (not filled with zeros)
- One machine is selected at a time so machine-specific scales remain interpretable

## Cache Files

Cache files are derived data, not source data. They are:
- Not committed to version control (the root `.gitignore` excludes `dashboard/cache/`)
- Regenerated by running `python preprocess.py`
- Used by the app for responsive interaction (avoids reloading millions of raw rows)

## Troubleshooting

**No data visible?**
- Run `python preprocess.py` first to generate cache files
- Check that `cache/` directory exists and contains `.parquet` and `.json` files

**Heatmap empty?**
- Verify date range overlaps with data range shown in sidebar
- Some machines have shorter date ranges (e.g., machine_04 only 12 days)

**Performance issues?**
- The app uses `@st.cache_data` for all data loading
- Preprocessing creates compact aggregates; raw CSV files are never loaded by the app
- If preprocessing is slow, consider Polars or a separate Rust tool (future enhancement)
